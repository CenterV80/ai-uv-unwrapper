# 研究計画と検証項目 — 複雑な形状の自動UV展開

このリポジトリは、複雑な形状のメッシュを自動でUV展開する手法の**研究用ツール**です。
汎用ツールや製品を目指すものではなく、手法を同じ条件で比較・検証するための基盤として使います。

## 1. 研究課題

| ID | 問い |
|---|---|
| RQ1 | 学習したシーム予測は、幾何だけの規則（二面角）や既存手法（xatlas）より、アーティストに近いシームを出せるか |
| RQ2 | ボクセル由来・画像→3D由来のメッシュ（鋭い折れ目がなく、表面がでこぼこ）でも有効か。性能はどれだけ落ちるか |
| RQ3 | 画像として見た「部品分け」（2DのAIによる要素分解）を加えると、シームは改善するか |
| RQ4 | 品質の差は、シームの位置と展開・パッキングのどちらに起因するか |

## 2. 現在のシステム（2026-11 時点）

詳細は [README](../README.md) を参照。

- シーム予測：エッジごとの幾何特徴量22種 → 2段のロジスティック回帰（2段目は近傍の予測値を使う）
- チャート化：しきい値 → 位相修正カット（境界ループ間の最短路）→ 分割（ウォーターシェッド）
  → LSCM → 歪み超過・UV自己重なりがあれば再分割
- パッキング：チャート形状のラスタ化による配置（4回転）
- 評価：`tools/bench.mjs`（5手法 × 指標一式）

## 3. 評価プロトコル

### データ
- **artist**：Khronos glTF-Sample-Assets のうち、アーティストがUV展開したモデル（`npm run setup:data`）
  - `split`：`unseen`（シーム予測の学習に未使用）を主結果とし、`train` は参考値とする
  - `reference`：正解として使える手作業のUV（`usable`）だけでシーム一致度を計算する。
    自動生成アトラス（1チャートあたり60面未満）やシームのないものは除外して、除外したことを記録する
- **voxel**（V5で作成）：artist をボクセル化・リメッシュしたもの。正解シームを写して持つ
- **image3d**（V6）：社内の画像→3Dパイプラインの出力。正解シームなし。`data/` に置き、**リポジトリにはコミットしない**

### 比較する手法
| 手法 | 役割 |
|---|---|
| `ours` | 学習シーム予測＋本パイプライン |
| `dihedral` | 同じパイプラインで、シームを二面角30°以上で決める（学習なしの基準） |
| `artistSeams` | 同じパイプラインに正解シームを入れる（シームが完璧な場合の上限。RQ4の切り分け用） |
| `artistUV` | アーティストのUVをそのまま測る（参照値） |
| `xatlas` | 既存の自動展開ライブラリ（既定設定） |

### 指標（`src/core/metrics.js`）
- **レイアウト**：チャート数（1000面あたり／アーティスト比）、正規化シーム長（シーム長 ÷ √表面積）
- **歪み**：面積歪み max(r, 1/r)、角度歪み σ1/σ2。面積加重の平均と95パーセンタイル
- **有効性**：反転面（3Dの向きをそろえてから判定）、UV重なり率（1024²ラスタ）、範囲外UV。
  有効 = 反転面積 ≤ 0.01%、重なり ≤ 0.1%、範囲外なし
- **シーム一致**：正解シームに対する適合率・再現率・F1（完全一致、および対角線1%以内の測地距離を許容する版）と、予測確率のAUC

### 再現性
- 結果は `results/<名前>/` に `results.csv` / `summary.json` / `summary.md` として出力する
- `summary.json` に、コミットID、Nodeのバージョン、パラメータ、データの場所を記録する
- `results/` と `data/` はGitの管理外。公開してよい集計だけを、このドキュメントに転記する

### V1. ベースラインの確立 ✅（2026-11-07、コミット `f49a323`、`results/baseline-v1`）
- **手順**：`node tools/bench.mjs --out results/baseline-v1`（既定パラメータ、15万面以下の174メッシュ）
- **unseen（学習に未使用）の結果**：15メッシュ（9モデル）。シーム一致度を計算できたのは8メッシュ
  （BoomBox、CesiumMilkTruck ×2、Corset、Duck、SheenChair ×3）。中央値は次のとおり

| 手法 | 有効率 | チャート/1000面 | チャート÷アーティスト | 面積歪みP95 | 角度歪みP95 | シームF1（許容1%） | シームAUC |
|---|---|---|---|---|---|---|---|
| ours | 87% | 7.8 | 2.2 | 1.457 | 1.049 | 0.704 | 0.829 |
| dihedral | 80% | 25.0 | 7.6 | 1.167 | 1.044 | 0.715 | 0.851 |
| artistSeams | 93% | 7.8 | 1.07 | 1.304 | 1.048 | 1.000 | – |
| artistUV（参照） | 47%※ | 7.8 | 1.00 | 1.439 | 1.433 | 1.000 | – |
| xatlas | 100% | 29.4 | 5.6 | 1.159 | 1.090 | 0.806 | – |

※アーティストのUVは、タイリングや左右の重ね置きなど意図的な配置のため、機械的な有効判定を満たさないことが多い。

- **読み取れること**（n が小さいため暫定。V2で検定する）
  1. **シームの位置の精度は、学習モデルが二面角を上回っていない**（AUC 0.829 対 0.851、F1 0.704 対 0.715）。
     RQ1は現時点で否定的。学習時の検証（別の分け方で AUC 0.860 → 0.868）とも食い違っており、標本の少なさが疑われる
  2. **チャート数は ours が最もアーティストに近い**（2.2倍。dihedral は7.6倍、xatlas は5.6倍）。
     ただし面積歪みP95は大きい（1.46 対 1.16）。チャート数と歪みのトレードオフで、シームの位置が良いからではない
  3. **正解シームを与えると、本パイプラインはアーティストとほぼ同じチャート数になる**（1.07倍、有効率93%）。
     チャート数の差の主因はシーム予測、という暫定結論を支持する
  4. **有効率の差**：ours の無効はほぼすべてUV重なり（チャートごとの許容0.5%以下の重なりが、全体で0.1%を超える）。
     xatlas は unseen で100%。重なりの許容値の見直しか、展開法の変更（V7）が必要
- **全データ（train を含む、181件・シーム評価83件）**：ours の F1 0.445、dihedral 0.351、xatlas 0.373。
  ただし学習データを含むため、手法の比較には使わない

### V2. 統計的な比較 ✅（2026-11-07、コミット `d047d16` 以降、詳細は `docs/results/v2-*-stats.md`）
- **方法**：`tools/stats.mjs`
  - 同じメッシュ上で手法を対にした比較：ウィルコクソン符号順位検定。有効率はマクネマー検定
  - 差の中央値の95%信頼区間：元モデル単位のクラスタ・ブートストラップ（4000回）
  - ホルム補正
  - 偶然の基準：予測と同じ本数のエッジをランダムに置いたときの値
  - ボクセル版は3解像度を平均して1件と数える
- **データ**：
  - アーティスト・元の形状：76メッシュ／26モデル（うち unseen 8）
  - アーティスト・ボクセル版：84元メッシュ
  - 生成した服：240着（V8）
  - 生成した服のボクセル版：240体
- **確かに言えること**（Holm補正後 p < 0.01）

| 主張 | どのデータで | 根拠（中央値） |
|---|---|---|
| どの手法も偶然よりは良い | アーティスト元形状、生成服、生成服ボクセル | 例：アーティスト元形状のF1(1%)：ours 0.50、偶然 0.19 |
| **ours は布の枚数がアーティストに最も近い** | アーティスト元形状（all） | アーティスト比：ours 約2.8倍、二面角 約5.0倍、xatlas 約6.0倍 |
| ours は xatlas より余計な切れ目が少ない | アーティスト元形状（all）、生成服ボクセル | 余計な割合：60% 対 72%、86% 対 89% |
| **その代わり、ours は面積歪みが大きい** | アーティスト元形状、両ボクセル版 | 面積歪みP95：ours 1.43、xatlas 1.14（元形状）。2.13 対 1.23（ボクセル） |
| **ours は UV の有効率で xatlas に負ける** | アーティスト元形状、両ボクセル版 | 生成服ボクセルでは ours 0%、xatlas 100% が有効（重なり） |
| ours は二面角より縫い目を見つける | 生成服、生成服ボクセル | 生成服ボクセルのF1(1%)：0.20 対 0.15、見つけた割合 32% 対 18% |

- **確かとは言えないこと**
  - アーティストのメッシュで、ours のシームの位置が他の手法より良いとは言えない（F1の差は有意でない）
  - unseen の8メッシュでは、どの比較も有意でない
  - アーティストのボクセル版では、許容3%のF1でどの手法も偶然と区別できない（ours 0.37、偶然 0.31）
- **注意**：
  - アーティストデータの all には学習に使ったモデルが含まれ、ours に有利
  - 生成した服では、前後の境目以外の縫い目（腰の切り替え・はぎ・袖付け・帯）に形の手がかりがない（V8の限界を参照）。
    形だけを見る手法は前後の境目しか見つけられず、どの手法も「見つけた割合」は約45%で頭打ちになる
- **RQ1への答え（現時点）**：
  - 学習したシーム予測の効果は小さい。はっきり言えるのは「枚数を抑える」ことで、その代わりに歪みと有効率を犠牲にしている
  - 縫い目の位置そのものの改善は、生成した服で小さな差（F1 +0.04）が出た程度

### V3. シーム予測モデルの改善 ⬜
- **仮説**：エッジを1本ずつ判定するのをやめ、メッシュの構造全体を見るモデル（グラフニューラルネット、SeamGen/SeamFlow型）にすると、F1が上がり細切れが減る
- **方法**：特徴量はそのままで、モデルだけを差し替えて比較する（アブレーション）。学習データを増やす効果も別に測る
- **注意**：artist データは数十モデルしかない。データを増やす場合は、ライセンス方針（CC0 / CC-BY のみ）を守る
- **環境**：GPU（会社のPC）

### V4. 画像としての部品分解（2DのAIによる要素分解）⬜ — 新規
- **仮説**：人と同じく「見た目の部品」（袖・襟・顔・髪など）でまず分けると、幾何の手がかりが乏しいメッシュ（ボクセル由来など）でもアーティストに近いシームになる（RQ3）
- **方法**
  1. 画像を用意する。次の2通りを比べる
     - (a) 画像→3Dパイプラインの**元画像**をそのまま使う
     - (b) メッシュを複数方向からレンダリングした画像を使う
  2. 2Dのセグメンテーションモデルで、画像上で部品に分ける（候補：SAM系。ライセンスは使う前に確認する）
  3. 各画像の分け方をメッシュの面に投影し、視点ごとの結果を投票で統合して、面ごとの部品ラベルを作る
  4. 部品の境界をメッシュのエッジに沿うよう整え（既存のウォーターシェッドやカットを流用）、「部品境界かどうか」をシーム予測の特徴量として追加する
- **比較**
  - 部品の特徴量あり／なし
  - 視点数（4 / 8 / 16）
  - 統合方法（多数決／信頼度による重み付け）
  - (a) 元画像 と (b) 再レンダリング
- **指標**：シームF1、チャート数のアーティスト比、角度歪み。部品境界とシームの一致率も追加する
- **想定される課題**
  - 視点による隠れや判定の食い違い
  - 部品とUVチャートの違い（1つの部品をさらに切る必要がある場合や、まとめるべき場合）
  - 処理時間
- **関連研究**
  - 2Dの知識を3Dに持ち上げる部品分割（PartSLIP、SAMPart3D など）
  - PartUV（部品単位のUV展開。ただし3Dで直接学習した PartField を使い、非商用ライセンス）
- **環境**：GPU（会社のPC）

### V5. 正解つきボクセル版データの作成 ✅（2026-11-07、コミット `636eefe`、`results/voxel-v1`）
- **作成**：`node tools/voxelize.mjs`（出力先 `data/voxel/`、Git管理外）
  - 入力：アーティストが手作業で展開したメッシュ（1チャートあたり60面以上、6万面以下）92個
  - 処理：ボクセル化（表面近くの帯 ＋ 外側からの塗りつぶし）→ Surface Nets → Taubin平滑化（6回）
  - 正解：新しい面ごとに元メッシュの最近傍の面を探し、そのUVチャートを写す。チャートの境界を正解シームとする
  - 解像度：最長辺を32 / 48 / 64分割
  - 評価したのは276メッシュ。同じ名前のメッシュの出力が上書きされ、15件減った（修正済み。次回の作成から一意の名前になる）
  - 品質：開いた境界なし、元の表面から2ボクセル以上離れた面なし。非多様体エッジは1000面あたり中央値0.46本（展開時にはシームとして扱われる）
  - 目視確認：Duckで、写したシームが元のUV境界（目・くちばし・羽・尾）と対応していることを確認。境界は面単位なのでギザギザになる
- **元メッシュとの対応比較（RQ2）**：同じ元メッシュについて、元の形状とボクセル版（3解像度の平均）を比べた。中央値は次のとおり

| 手法 | unseen（n=7）シームF1 | unseen シームAUC | 全体（n=59）シームF1 | 全体 シームAUC |
|---|---|---|---|---|
| ours | 0.704 → 0.192 | 0.829 → 0.527 | 0.530 → 0.183 | 0.842 → 0.576 |
| dihedral | 0.715 → 0.201 | 0.851 → 0.590 | 0.413 → 0.160 | 0.847 → 0.662 |
| xatlas | 0.772 → 0.169 | – | 0.496 → 0.170 | – |
| artistSeams | 0.979 → 0.975 | – | 0.974 → 0.853 | – |

- **ボクセル版だけの集計（unseen 24メッシュ、シーム評価20件）**

| 手法 | 有効率 | チャート÷アーティスト | 面積歪みP95 | シームF1 | シームAUC |
|---|---|---|---|---|---|
| ours | 75% | 0.55 | 2.04 | 0.142 | 0.531 |
| dihedral | 54% | 0.73 | 2.15 | 0.185 | 0.593 |
| artistSeams | 100% | 1.10 | 1.80 | 0.965 | – |
| xatlas | 100% | 1.30 | 1.17 | 0.124 | – |

- **読み取れること**
  1. **ボクセル由来の形状では、幾何に基づくシーム予測はほぼ機能しない**（RQ2）。
     ours の AUC は 0.83 から 0.53 へ下がり、偶然（0.5）とほぼ同じ水準になった。
     dihedral と xatlas も同様にF1が0.7〜0.8から0.2以下に下がった。学習モデルの劣化が最も大きい
  2. 正解シームを与えれば、本パイプラインはボクセル版でも高い一致（unseen F1 0.975）と100%の有効率を保つ。
     写した正解シームが展開に使える品質であることの確認にもなる
  3. ours はシームを入れなさすぎる（チャート数がアーティストの0.55倍、面積歪みP95 2.04）。
     学習時に決めたしきい値が、折れ目のない形状では高すぎる
  4. 無効の原因はほぼすべてUVの重なり（ours 93件中85件以上）
  5. 解像度を上げると、どの手法もF1が上がる（ours：v32 0.06 → v64 0.17）。
     許容つきF1にはシームの密度に応じた「偶然でも一致する分」があり、その影響の可能性が高い。
     **偶然の水準（ランダムなシームでのF1）を基準として示すことを、V2で追加する**
- **訂正（画像レポートでの確認後）**：上の「偶然に近い」は言い過ぎだった。
  切れ目を3Dで重ねて見ると、ボクセル版では**正しい場所のすぐ横を平行に切っている**例が多い（角が丸くなるため）。
  許容を対角線の1%から3%に広げると、トラックの ours は「見つけた割合（長さ）」が7% → 49%、「余計な割合」が85% → 18%になる。
  劣化は確かにあるが、その一部は位置のわずかなずれで、許容幅の決め方に結果が強く依存する。
  形状の作り方に合わせた許容幅の決め方を、V2で検討する
- **画像つきレポート**：`tools/report/`（collect → render → build-html）。5つの代表モデルについて、元の形状とボクセル版で、正解と各手法の切れ目を色分けして表示する
- **V4への示唆**：形状の手がかりが失われると、アーティストの切れ目を見逃す割合が大きく増える。見た目の部品情報を加えるV4を検証する根拠になる

### V8. 正解シームつきモデルの自己生成（服）✅（初版）
- **目的**：学習に未使用で正解つきの評価データが8メッシュしかなく、統計的に何も確定できない（V2）。
  正解つきのモデルを自分で大量に作れるようにし、検証を成立させる
- **方法**：`node tools/gen-garments.mjs --n 60 --seed 1`（出力 `data/garments/`、Git管理外。乱数の種で再現できる）
  - 実際の服と同じく、型紙のパーツを縫い合わせた形として作る。**正解のシーム = 型紙パーツの境界（縫い目）**
  - 種類と変化：
    - トップス：普通の袖 / ラグラン袖 / 袖なし、半袖 / 長袖、カフス・襟の帯・裾布の有無、丈と身幅
    - パンツ：長ズボン / ショートパンツ、ウエストバンドの有無、左右の前中心・後ろ中心の縫い目
    - スカート：2 / 4 / 6枚はぎ、広がり方、ウエストバンドの有無
    - ワンピース：上半身とスカートを腰で切り替え
  - 生成ルール：
    - 前身頃と後身頃は別パーツ（脇・肩・股下で縫う）
    - 袖は前後で別パーツ（2枚袖）
    - 帯（襟・裾・カフス・ウエスト）は別パーツ
  - ボクセル版：`node tools/voxelize.mjs --data data/garments --res 48 --out data/garments-voxel`。
    生成した服は布1枚の面なので、ボクセル化すると厚みのある布（内側と外側の2面）になる
- **確認**：
  - 4種類それぞれで、縫い目の位置を画像で確認した
  - 正解シームで展開すると、全件が有効で、チャート数とパーツ数が一致した
- **限界**：
  - 正解は「縫い目」という生成ルールで決まる。アーティストのUVの切り方（目立たない位置に切る、など）とは一致しない場合がある
  - 生成ルールに合わせ込んだ手法が有利になりうるので、アーティストの実データ（V1、V5）を本物の基準として残す
  - 斜めの縫い目（ラグラン袖）は、面の並びに沿ってギザギザになる（評価の許容幅の範囲内）
  - 将来、生成データでシーム予測を学習する場合は、学習用と評価用を乱数の種で分ける（評価用は `--seed 1`）
  - **評価で分かった限界**：
    - 縫い目の両側で布が平らにつながるため、前後の境目以外の縫い目には形の手がかりがない。実物の服には縫い代のふくらみがある
    - 改善案：縫い目に沿ったふくらみの高さを生成時のパラメータにする。0（手がかりなし）から実物程度まで変えれば、「形の手がかりの強さ」と検出性能の関係を制御された条件で測れる
    - 生成した服のボクセル版では、ours と二面角だけの展開が**全件無効**になった（UVの重なり）。xatlas は全件有効。V7で原因を調べる
